# Statement 加载性能与复测方法

本报告对应 [issue #4](https://github.com/SII-MATH/Formaliscope/issues/4)，比较 dev `a0690ff` 与本次优化。测量在同一台开发机器、同一 Chromium、同一份 6,222 条声明候选快照和临时空数据库上进行，使用合成预览身份。未读取生产数据库，未安装运行快照，也未部署正式服务器。

## 优化方法

1. 先区分正文可读与个人审阅表单可用，分别测量首次导航、刷新到 hash 指定声明、不同条目切换、缓存内重访和超大声明。
2. 同时记录 API 请求瀑布、清单首字节与下载耗时、实际编码/解码字节数、JSON 解析耗时和主线程长任务，定位网络往返、载荷与重复计算各自的成本。
3. 优先移除不必要的等待，再减少重复工作。每次只复用只读证据；个人审阅状态、历史和身份都保留独立请求与失效规则。
4. 在相同的正常/慢速网络条件下顺序复测，保存全部样本、环境和被测模块摘要，报告中位数、p95、回退与未改善项。以后沿用本脚本和这些场景，发现新的瓶颈再优化。

## 最终改动

- 配置与初次身份查询并行；身份初始化复用返回值，启动不再第二次请求 `/api/auth/me`。建立/恢复身份及改名后仍重新读取身份。
- 清单请求携带 hash 或 `auto`，只在 `initial_evidence.id` 与前端最终选择一致时预热证据缓存。有效 hash 保持优先级；目录、标签、无效 hash 和服务端候选不一致时保持原来的选择规则并正常回退。
- 证据缓存按最近使用淘汰，仍限制为 12 条；个人状态和历史不缓存。退出后清空缓存，旧身份的迟到响应与 401 不会覆盖新身份。
- 搜索文本在清单加载及审阅状态变化时更新；筛选排序结果按目录、范围、排序、检索、标签缓存；标签计数只在标签窗口打开时计算。
- 清单 JSON 去除无意义的空白，并按 `Accept-Encoding` 协商 gzip；尊重 `q=0`，返回 `Vary: Accept-Encoding`，仍使用 `Cache-Control: no-store`。证据指纹、数学内容和其他 API 的 ETag 规则不变。

hash 指定且命中嵌入证据的启动链从「config → me → me → catalog → evidence」变为「config 与 me 并行 → catalog（含 evidence）」。个人状态另行读取。启动 API 总数从 6 次减至 4 次（减少 33.3%），身份查询 2 次减至 1 次，首条独立 evidence 请求 1 次减至 0 次。无效 hash 或自动候选与筛选结果不一致时仍会单独请求正确条目的证据。

## 测量口径与限制

- 正常网络：Chromium CDP 模拟 80 ms 延迟、上下行 5 Mbps，前后各 7 轮。慢速网络：180 ms、1.5 Mbps，前后各 5 轮。没有额外 CPU 限速。每轮使用新浏览器上下文；刷新复用该上下文的 HTTP 缓存。
- 前后均启用同一 gzip 代理模拟器。线上静态资源 GET 响应已确认有 `Content-Encoding: gzip`；未持有生产会话核实线上 catalog 响应。此报告不把「未压缩 → gzip」的体积收益算作线上改善。
- 正文时间由页面内 MutationObserver 确认当前声明正文已填入且可见，再等待两次 requestAnimationFrame，记录一次绘制机会之后的时间；这是可复现的可见代理指标，并非浏览器提供的精确文字 paint 时间。表单时间是个人状态已载入、意见框可用的时间。
- 首屏和刷新目标都是 `challenge1`。暖切换通过真实搜索结果按钮打开 `standardH6Square`、`NonzeroSurvival`；搜索过程不计入点击耗时，暖切换列表通常只有一个搜索结果。缓存重访为回到 `challenge1`，个人状态仍重新读取。
- 超大声明是同一快照内源码最长的 `KIP126.LinE2.RawData.relationChunks`，源码 UTF-8 共 3,739,377 字节，完整内容仍按原规则显示，没有截断或修改。
- 首字节、下载、字节数取浏览器 ResourceTiming；CDP 网络模拟与真实链路的等待分布可能不同。JSON 解析由同一探针在前后都执行 response.text() 后计时 JSON.parse，不把网络读入时间计作解析。长任务合计只包含浏览器报告的超过 50 ms 的任务，不能代表全部 CPU 时间。
- 原始 `resources` 是各场景结束时的累计 API 瀑布；`parses`、长任务合计按本场景开始时间过滤。延迟加载的公式资源可能在刷新/关闭上下文时被取消，不参与正文指标。
- p95 使用排序样本的最近秩近似；7 个和 5 个样本的 p95 接近最大值，暖切换分别有 14 个和 10 个样本。共享机器会有波动；这些是受控本机浏览器结果，不是线上测量或统计显著性的保证。
- 原始结果仅含指标、快照摘要、源码提交和模块 SHA-256，不含快照正文、数据库、恢复凭证、Cookie 或个人审阅记录。

全部 Python 测试通过：应用 230 项、statement workflow 50 项。全部 6 组前端测试、所有前端模块语法检查及 3 个部署脚本语法检查通过。Linux systemd 验证由 PR CI 执行。

新增/扩展验证覆盖：启动身份复用、初始证据命中与不匹配、目录/hash/无效编码、配置主题标签、状态改变后的检索与筛选失效、缓存淘汰、401 和旧身份请求、迟到的 catalog/evidence/review-state、草稿保存失败与身份过期时保留输入。现有草稿完成、历史分页、身份隔离及前进/后退恢复测试继续通过。

## 复测

脚本为 [benchmark_statement.py](benchmark_statement.py)，Playwright 和 Chromium 仅是可选开发测量依赖，不是应用运行依赖。使用新的候选路径生成预览快照即可，不需要安装到运行数据目录。

```bash
git archive a0690ff | tar -x -C /tmp/formaliscope-loading-before
# 为稳定复现本报告，单独归档 KIP126 的以下提交并构建候选：
git -C /path/to/KIP126 archive 38554617a4465bbce021b88977af660b90d83697 \
  | tar -x -C /tmp/formaliscope-loading-source
python3 -m review_app build --statements --source /tmp/formaliscope-loading-source \
  --source-commit 38554617a4465bbce021b88977af660b90d83697 \
  --output /tmp/formaliscope-loading-6222.json

python3 review_app/benchmark_statement.py \
  --app-root /tmp/formaliscope-loading-before \
  --snapshot /tmp/formaliscope-loading-6222.json --proxy-gzip --repeat 7 \
  --label a0690ff --output /tmp/statement-before-normal.json
python3 review_app/benchmark_statement.py \
  --snapshot /tmp/formaliscope-loading-6222.json --proxy-gzip --repeat 7 \
  --label optimized --output /tmp/statement-after-normal.json
# 慢速网络：两条命令都使用 --repeat 5 --rtt-ms 180 --mbps 1.5
```

归档前先创建两个空临时目录；候选输出路径必须尚不存在。`--source-commit` 归档仅用于本机预览，生产构建仍须从干净检出生成。被测模块和探针的 SHA-256 保存在每个结果的 `environment`，便于确认比较的确切实现。
