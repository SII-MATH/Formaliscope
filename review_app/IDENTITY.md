# 账号密码与用户管理

默认 `REVIEW_AUTH_MODE=name`，网页注册填写姓名和 8–128 字符密码。账号 ID 随机生成；姓名作为可读登录账号，前后空格、全角兼容字符及字母大小写按统一规则比较。数据库已有的姓名（包括停用账号）不能再次注册；改名同样检查冲突。姓名未经学校核验，不代表经过验证的学籍身份。

日常使用姓名或完整账号 ID 与密码登录。浏览器通过 HttpOnly / SameSite=Strict Cookie 保持登录 30 天，正式 HTTPS 入口同时设置 Secure。密码使用独立随机盐和 PBKDF2-HMAC-SHA256（600,000 次迭代）保存，明文不进入数据库、日志或身份接口。名字和 ID 都不能作为免密码的恢复凭证。

## 本次升级

schema 12 建立密码凭证，schema 13 移除姓名身份的恢复码摘要、关闭恢复和重新生成接口，初始化所有已有账号密码为 `12345678`，要求首次登录修改，并撤销升级前会话。恢复码不能用于登录；账号菜单不再提供恢复码功能。重复迁移不会再次初始化密码。

登录页或改密页展示一次“登录方式已更新”通知，说明取消恢复码、账号密码入口、初始密码与手动修改方式。确认后在当前浏览器、当前应用路径记录已读；浏览器禁止本地存储时仍能正常显示和关闭。

账户菜单的“账号信息 / 修改密码”打开 `/password`，显示完整账号 ID。修改密码须输入当前密码，并退出其他设备，当前浏览器继续登录。初始密码不能作为新密码保存，新密码也不能与当前密码相同。服务器同时限制初始密码身份访问审阅页面、写入接口和管理后台。

## 管理员与找回密码

管理员由服务器操作员创建，第一位注册学生、填写“管理员”或提交角色字段都不会获得管理员权限。在候选应用目录执行：

```bash
sudo -u formaliscope-review python3 -m review_app create-admin \
  --data-dir /var/lib/formaliscope --name '管理员姓名' \
  --output /var/lib/formaliscope/admin-account.txt
```

私人账号文件以 0600 排他创建，包含账号 ID、初始密码和首次改密说明，已有文件不会覆盖；终端只输出身份 ID、姓名和文件路径。账号文件属于用户数据，不提交 Git、不上传发布包、不放网页目录。管理员从普通登录页进入，先修改初始密码，账户菜单出现“管理后台”。生产预检只读确认启用的管理员身份存在。

忘记密码请联系全局管理员，在用户详情选择“重置此用户的密码”，核对完整 ID 并输入管理员自己的密码确认。指定账号密码重置为 `12345678`，所有会话退出，下次登录须修改密码。普通用户、仓库版本管理员、停用账号及尚未改初始密码的管理员不能重置。管理员修改自己的密码走 `/password`；不提供自助按姓名找回。

公开入口使用 HTTPS，服务器仍仅监听 loopback。代理、Origin 与 Cookie 配置见 [DEPLOYMENT.md](DEPLOYMENT.md)。正式模式无需邮箱服务；显式 `REVIEW_AUTH_MODE=email` 的历史邮箱验证码模式仍兼容，`--preview` 仅用于本机演示。

## 确认重复账号后的离线合并

只有本人确认重名账号属于同一人后，操作员才指定准确的 source 和 target。先备份、停止服务，再执行：

```bash
sudo -u formaliscope-review python3 -m review_app merge-accounts \
  --data-dir /var/lib/formaliscope --source '旧账号ID' --target '主账号ID'
```

每条历史判断保留记录 ID、结论、备注、时间和证据，并记录原审阅账号。若请求 ID 与目标账号冲突，仅重新生成请求 ID，并在私有合并档案保留映射。草稿归入主账号；相同条目与证据的草稿冲突时保留时间较新的可编辑检查点，原始草稿均归档。管理员与仓库权限合并；源账号从注册目录移除，旧 ID 作为主账号登录别名保留，两个账号的旧会话都退出。主账号重置为初始密码并要求修改；重复执行同一合并不会再改动数据。不能自动按姓名合并未经确认的旧账号。

已有邮箱 reviewer 如需接到密码入口，由操作员核对准确身份后使用 `bind-account --reviewer <原身份键> --name <唯一姓名> --output <私人账号文件>`；保留原 owner 和判断，管理员权限须显式加 `--admin`。旧 `bind-recovery` 命令已移除。

## 用户与审阅后台

全局管理员进入 `/admin` 默认查看完整注册账号、启用状态、角色、参与情况和最近审阅时间。用户列表的有效判断数合计各仓库当前版本，历史保存数包含所有版本。用户详情按页展示指定仓库的已提交审阅，区分有效、已被后续判断替代及依据已变化记录。未参与审阅的账号也显示；现有数据没有注册时间，后台不推断日期。

仓库版本管理员只访问获授权的汇总，全站用户目录与详情须全局管理员权限。后台不展示未提交草稿、登录会话、密码哈希、已取消的恢复码或内部机器评估。显示姓名意外含旧恢复码样式字符串时仍予以隐藏。

## 接口与存储

- `GET /api/config`：认证模式与更新通知版本；`GET /api/auth/me`：当前 user_id、姓名、角色与 must_change_password，不返回凭证。
- `POST /api/auth/register`：display_name 与 password；返回 user_id 与会话 Cookie，已有姓名返回 409。旧客户端未传密码时使用初始密码并强制改密。
- `POST /api/auth/password-login`：account 与 password，签发主账号会话。
- `POST /api/auth/password`：current_password 与 new_password，修改自己的密码。
- `POST /api/admin/reset-password`：reviewer 与管理员 current_password，重置指定启用账号。
- `POST /api/profile`：修改不冲突的姓名；`POST /api/auth/logout`：退出当前浏览器。
- `GET /api/admin/users` 与 `/api/admin/user?reviewer=<ID>&dataset=<ID>&cursor=0&limit=25`：只读目录与已提交历史，单页最多 100 条。

所有写入检查 Origin 与 JSON；注册和密码操作有限流。密码操作每 IP 每 60 秒最多 20 次，同一账号跨姓名、旧 ID、新 ID 和 IP 每 60 秒最多 10 次密码登录，成功与失败都计数。只支持单服务进程。备份保留身份、角色、密码哈希、判断、草稿和合并档案，清除会话与验证码；auth-pepper 重新生成不影响密码。迁移后的数据库不能用旧版应用运行，回退须使用升级前完整备份。
